# 6. Zigzag Conversion — Interview Preparation / Chuẩn bị phỏng vấn

## 1. 30-second pitch / Cách trình bày trong 30 giây

**EN:** I simulate only the row movement instead of building a two-dimensional zigzag grid. I keep one `StringBuilder` per row, a current row index, and a direction that is either down or up. Each character is appended to its current row; at the first and last rows I reverse direction. Finally I concatenate the row builders. This is `O(n)` time and `O(n)` space for the output storage.

**VI:** Em chỉ mô phỏng chuyển động row thay vì dựng grid 2D. Em giữ một `StringBuilder` cho mỗi row, current row và direction lên/xuống. Mỗi character được append vào current row; khi chạm row đầu hoặc cuối thì đổi hướng. Cuối cùng nối các row. `O(n)` time và `O(n)` space.

---

## 2. Core practice questions / Câu hỏi cốt lõi

### Q1

**Q (EN):** Why don't you need to store columns or spaces?

**Q (VI):** Vì sao không cần lưu column hoặc spaces?

### Short answer (EN)

The output is read row by row, so only the ordered characters belonging to each row matter.

### Trả lời ngắn (VI)

Output được đọc theo row, nên chỉ thứ tự character thuộc từng row là quan trọng.

### Standard answer (EN)

The visual horizontal positions exist only for presentation. They do not affect the order of characters within a row. If I append each character to the correct row as the zigzag path moves, concatenating the rows reproduces the required output exactly.

### Trả lời chuẩn (VI)

Vị trí ngang chỉ phục vụ hình minh họa, không ảnh hưởng thứ tự character trong cùng row. Chỉ cần append đúng row rồi concatenate các rows là đủ.

### Deep answer (EN)

This is a state-projection optimization: the full 2D path contains more information than the final readout needs. The row coordinate is the sufficient state; the column coordinate can be discarded.

### Trả lời sâu (VI)

Đây là tối ưu bằng state projection: full 2D path chứa nhiều thông tin hơn output cần. Row coordinate là sufficient state; column có thể bỏ.

---

### Q2

**Q (EN):** Why special-case `numRows == 1`?

**Q (VI):** Vì sao phải special-case `numRows == 1`?

### Short answer (EN)

There is no vertical movement; every character stays in the only row.

### Trả lời ngắn (VI)

Không có chuyển động dọc; mọi character đều nằm ở row duy nhất.

### Standard answer (EN)

Without the early return, the usual boundary-toggle logic has both the top and bottom boundary at row zero and can move to an invalid row. Returning the original string is both correct and simpler.

### Trả lời chuẩn (VI)

Nếu không early return, top và bottom boundary đều là row `0`, direction logic có thể đi ra index sai. Trả input trực tiếp vừa đúng vừa đơn giản.

---

### Q3

**Q (EN):** What are the complexities?

**Q (VI):** Độ phức tạp là gì?

### Short answer (EN)

`O(n)` time and `O(n)` storage for the row builders and result.

### Trả lời ngắn (VI)

`O(n)` time và `O(n)` storage cho row builders/output.

### Standard answer (EN)

Every input character is appended exactly once to a row and copied once into the final builder. The total content stored across all rows is `n` characters.

### Trả lời chuẩn (VI)

Mỗi input character append đúng một lần và copy một lần khi nối output. Tổng character lưu trong các row bằng `n`.

---

### Q4

**Q (EN):** Is there a formula-based solution?

**Q (VI):** Có solution dùng công thức không?

### Short answer (EN)

Yes. The zigzag repeats every `2*numRows-2` characters, and each row can be generated by index arithmetic.

### Trả lời ngắn (VI)

Có. Zigzag lặp theo cycle `2*numRows-2` và có thể tính index từng row bằng công thức.

### Standard answer (EN)

The formula approach can reduce the need for row buffers, but middle rows have both vertical and diagonal positions, which makes the indexing less intuitive. I prefer simulation unless memory constraints strongly favor the formula.

### Trả lời chuẩn (VI)

Formula có thể giảm row buffers nhưng middle rows có cả vertical và diagonal positions nên indexing khó hơn. Em ưu tiên simulation nếu không có constraint đặc biệt.

## 3. Code walkthrough / Giải thích code

**Q (EN):** Can you walk me through the implementation?

**Q (VI):** Bạn có thể giải thích implementation không?

**EN:** I create one builder for every row. Starting at row zero and moving down, I append each character. Whenever I am at row zero I set the direction downward; whenever I reach the last row I set it upward. Then I move one row in that direction. After processing all characters I concatenate all row builders.

**VI:** Em tạo builder cho mỗi row. Bắt đầu row `0` và đi xuống, append từng character. Ở row `0` đặt direction xuống; ở last row đặt direction lên. Sau đó di chuyển một row theo direction. Cuối cùng concatenate các row builders.

---

## 4. Common interviewer traps / Bẫy thường gặp

- Quên `numRows == 1`.
- Dựng matrix khổng lồ chỉ để giữ spaces.
- Đổi direction sai thời điểm.
- Không giải thích cycle/formula alternative khi được hỏi.

- direction toggle — đổi hướng
- concatenate rows — nối các hàng

- cycle length — độ dài chu kỳ
